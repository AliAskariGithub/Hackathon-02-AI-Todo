## Prompt

Update Project Constitution: The Evolution of Todo (Phase-IV)

## 1. Core Mission & Philosophy

* **The "Agent-First" Mandate:** This project is built entirely through Spec-Driven Development (SDD). No manual code or infrastructure YAML is permitted. All changes must originate from a specification file (`/specs`).
* **The Evolution:** Every phase must build upon the previous. Phase-IV must wrap the Phase-III Agentic Chatbot into a scalable, resilient, and observable Kubernetes environment.
* **Cloud-Native Excellence:** Prioritize portability, horizontal scalability, and automated recovery.

---

## 2. Structural & Architectural Standards

### **Infrastructure-as-Code (IaC)**

* **Helm Primary:** All Kubernetes resources must be managed via Helm Charts in the `/charts` directory. Raw manifests are for temporary debugging only.
* **Stateless Services:** Both Frontend and Backend must remain stateless. Persistence is offloaded to Neon PostgreSQL (external) or managed K8s volumes.
* **Standardized Labels:** Every resource must include `app.kubernetes.io/name`, `app.kubernetes.io/instance`, and `version` labels.

### **Containerization Standards**

* **Multi-Stage Builds:** All Dockerfiles must use multi-stage builds to minimize image size and maximize security.
* **Non-Root Execution:** Containers must not run as `root`. Use a dedicated `appuser` within Dockerfiles.
* **Semantic Versioning:** Images must be tagged with semver (e.g., `v1.0.4`) and git-sha. Never use `latest` in production manifests.

---

## 3. AIOps & Agent Governance

### **Tool-Specific Responsibilities**

* **Claude Code:** The Orchestrator. Responsible for writing `/specs`, generating `/plans`, and coordinating other agents.
* **Docker AI (Gordon):** The Architect. Responsible for generating, auditing, and optimizing all `Dockerfile` and `docker-compose` configurations.
* **kubectl-ai:** The Deployer. Used for generating initial Kubernetes resource templates and scaling commands.
* **Kagent:** The SRE. Responsible for cluster health audits, resource optimization, and troubleshooting "CrashLoopBackOff" events.

### **The Safeguard Clause**

* Any code or YAML generated by an AI agent must be reviewed by the "Technical Lead" (the user) before final deployment to the `minikube` cluster.

---

## 4. Development Workflow (SDD 2.0)

1. **Draft:** Create/Update a spec in `/specs/phase-iv/`.
2. **Plan:** Run `/sp.plan` to generate the implementation blueprint.
3. **Execute:** Use the appropriate AIOps tool (Gordon/kubectl-ai) for the task.
4. **Validate:** Use `kagent "check health"` to confirm successful deployment.
5. **Record:** Every successful iteration must be logged in the project's Prompt History Record (PHR).
